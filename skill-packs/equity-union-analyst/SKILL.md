# 权益投放分析（银联权益 · 账号维度）

适用：权益投放的消耗、订单 / 签约 / 转化漏斗、自营收入与三方佣金、ROI / 回本、部门或账号对比、环比异常。
数据：平台表「权益-账号维度消耗统计表」。用 `list_metrics` / `query_metric` 取数，指标口径已在平台统一定义，套餐范围已由平台自动限定；比率类指标由平台先汇总再相除，直接引用，不要自己重算。

## 五条硬口径

1. **套餐只有两类**：`常规套餐` = 自营，`三方支付套餐` = 三方 / CPA。其余取值不在业务口径内，平台已过滤，不解读、不提及。签约、转化、留存类指标只对常规套餐有意义，回答时先声明这一点。
2. **收入按业务属性分叉，不可相加**：自营看实付金额 / 净收入；三方看佣金。三方没有实付金额概念；佣金在自营里是成本，不是收入。ROI 自营、三方分别算，不做合并 ROI。
3. **归属口径**：部门口径（任哥 = 投放一部权益一组 + 二组；小炭 / 达人部门；伯都）和账号口径（存量 = 子墨 = 账号「白驹存量」）已由平台解析好，见上下文的「口径解析」，直接用，并在回答里写明用的是部门口径还是账号口径。**「白驹」有歧义**：不要自己选，也不要只追问，把两种口径各算一遍并列给出，标清哪一列是哪个口径。
4. **三列恒为空**：商户、商户名称、支付渠道在本表是 NULL，不能筛选或分组。用户要按商户 / 支付渠道拆分，直接说明本表做不到，需要换明细表。
5. **订单与消耗不同时间轴**：订单类指标按队列首单日统计，消耗类按消耗发生日统计。所以**日级 ROI 和转化率会明显抖动，周 / 月口径才可靠**；小时级只能看消耗和流量，不能看转化。

## 取数方式

- 单点总量：`query_metric`，「今天 / 昨天」用 `days=1`，「近 7 天」用 `days=7`；结果自带「数据截止日期」。
- 趋势和异常日：加 `daily=true`，结果含逐日值、最高 / 最低日、日均和异常日。比率的日级值抖动，趋势以整个窗口为准。
- 拆分和排名：用 `group`（部门、账号、优化师、套餐、媒体、是否续费等）。排名只用效率指标，分母太小的组不参与排名，并说明样本小。
- 口径解析给出的部门 / 账号 / 套餐筛选，用 `filters` 传入。
- 用户数是各行内按手机号去重后的人数，跨行（多日、多账号）累加会重复；多切片汇总时必须写成「含重复的人次」，不要当作去重用户数。
- 续费行也参与统计；只看新增用户的漏斗时，加筛选 `is_renew = 否`。
- 三方不看签约漏斗，看成功用户数和佣金。
- 问「为什么涨 / 跌 / 变差」：先用 `query_metric` 看总体，再用 `attribute_change` 定位（口径解析给出的范围用 `filters` 限定）。比率指标的变化分两类：**效率效应**是某个账号自己的转化 / 效率变了，**结构效应**是各账号占比变了（停投、放量都会体现在这里）。要分清是哪一类，并指出贡献最大的账号；原因只写成待验证的假设。

## 缺省值与追问

信息够就直接算，用缺省值并在回答里声明假设；时间范围、对象、指标缺失时不要为此追问。只有目标完全无法判断时才用 `ask_user`，且最多问两个问题。

## 做不到的事

按商户 / 支付渠道拆分；精确的全局去重用户数；单个订单追溯；小时级转化率；剔除无订单消耗后的「有效订单消耗」。遇到时直接说明原因和替代数据源，不要用估算值填空。
