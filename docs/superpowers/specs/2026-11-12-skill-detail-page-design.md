# Skill 详情页设计

日期：2026-11-12

## 目标
把 Skill 的长配置从右侧抽屉改到整页详情，交互对齐「表管理 → 表详情」：列表保留，点进去用页签分别编辑基本信息、提示词、引用的表和版本管理，长文本有足够空间，不再挤在约 620 像素的抽屉里。

成功标准：管理员能在一个整页里完成某个 Skill 的名称、提示词（或路由规则）、引用表清单的编辑并保存；也能在同一页做灰度、发版和回滚。原有抽屉配置入口去掉后，列表页不再承担这些长表单。

## 已确认的决定
- 列表页保留，点击 Skill 进入整页详情（与表管理进入表详情相同）。
- 详情页四个页签：**基本信息**、**提示词**、**引用的表**、**版本管理**。
- 引用的表对应规范包里已有的 `spec.tables`（数组，支持多张表）；用户未在对话里指定表时，分析用它作为默认取数范围。这个清单要能在详情页里编辑，不必跟代码包一起发版。
- 新版本仍先存成「未发布」，再到版本管理里灰度或正式发版。
- 权限仍走「Skill 配置」的查看 / 编辑权限。

## 现状（读代码得到）
- 列表在 `assets/portal/page-skill-management.js`。新增 Skill、新增版本、版本管理、版本详情都是右侧 `el-drawer`（约 560–640 像素）；提示词输入框只有 6 行。代码注释已写明：抽屉曾经把底部按钮裁掉，才从弹窗改成抽屉，空间仍然不够。
- 网关 `PUT /v1/skills/:id/config` 目前只接受图标、标题、描述、展示文案、排序、上线、提示词、场景、澄清、资产范围、回答契约、兜底技能、路由规则、灰度用户，**不接受表清单**。
- 表清单写在 Skill 规范包的 `skill.json` → `spec.tables`。例如「权益投放分析 Skill」是 `["权益-账号维度消耗统计表"]`。分析时会按用户权限过滤后，作为默认取数范围。门户界面现在改不了它。
- 表详情是独立页面「表详情」：`el-page-header` 返回表管理，中间页签，底部保存。侧栏高亮仍落在「表管理」。Skill 详情沿用这套页面切换，不新做 hash 路由。

## 1. 页面结构与交互
新增独立页面「Skill 详情」，侧栏高亮「Skill 配置」。进入方式与表详情一致：`bridge` 记下当前 Skill，再 `setPage("Skill 详情")`。

- 顶栏：`返回 Skill 管理` + `Skill 名称`（可加当前版本号）。浏览器后退或点返回都回到列表。
- 列表页：保留搜索、上线开关、「＋ 新增 Skill」。行内操作收成「详情」（或点名称进入）。不再出现「新增版本」「版本管理」。
- **新增 Skill**：只弹一个短表单，必填名称；创建成功后立刻进入该 Skill 的详情页补全其余字段。不要再为新增打开现有那种长抽屉。
- 只读用户（无编辑权限）可以进入详情页查看，但不能改、不能灰度 / 发版 / 回滚。
- 原有配置抽屉全部去掉。灰度仍可用小对话框勾选测试用户（这不是长表单）。查看某个历史版本快照，在版本管理页签里展开或用只读面板展示，不再另开一层配置抽屉。

## 2. 四个页签

### 基本信息
名称、图标、描述、展示文案、排序、上线状态。字段与现有创建 / 新版本表单一致，只是放到整页里。未保存的修改离开页签或返回列表前要提示，避免丢掉。页底「取消 / 保存」与表详情的基本配置相同。保存基本信息按**新版本**写入（状态「未发布」），不直接覆盖已发布版本的对外内容。列表上的上线开关仍可即时改启用状态，不必为此新建版本。

### 提示词
普通 Skill：整页大文本区编辑分析指令，高度吃满工作区，支持长文，不再限制为 6 行。页底同样是「取消 / 保存」，保存方式与基本信息相同（存为未发布的新版本）。

路由型 Skill（`kind === 'router'`）：本页不展示提示词，改为编辑关键词规则和兜底技能（现有抽屉逻辑原样搬过来，只是有了整页空间）。保存规则同样生成未发布新版本。

### 引用的表
可增删的表清单，多选或从网关认识的表里添加，不限制张数。只允许加入网关认识的表；已下线、无权限或已从网关消失的表要标出来，保存时提示并允许先移除。空清单表示不预置默认表，对话里再指定。

保存引用的表要写回该 Skill 的 `spec.tables`，即时生效（分析默认取数范围立刻变化），**不必**为此新建版本。若当前环境没有连上网关，只更新页面里的原型数据，并明确提示没有写到服务端。

### 版本管理
展示该 Skill 的版本列表：版本号、说明、操作人、时间、状态（未发布 / 灰度中 / 已发布）、当前版本标记。操作与现在一致：未发布可灰度，灰度中可调整灰度或发版，非当前版本可回滚，任意版本可查看快照（基本信息、提示词或路由规则、当时的说明）。发版前仍要确认。

「新增版本」不再作为列表行按钮。用户在基本信息或提示词里保存，就会产生未发布版本，然后到本页签处理灰度和发版。

## 3. 数据与接口
沿用现有 `GET /v1/skills` 与 `PUT /v1/skills/:id/config`。为支持引用的表，扩展 PUT：请求体增加 `tables`（字符串数组）。服务端写入该 Skill 规范包的 `spec.tables`（没有 `spec` 就创建），并做校验：

- 必须是数组，元素是表名字符串，去重、去空；
- 只接受网关认识的表，否则 400 并返回未识别的表名；
- 张数上限与现有分析侧能力对齐即可，第一版不人为卡在很小的数字（可设一个防护上限，例如 100）；
- GET 列表 / 详情要把 `tables`（即 `spec.tables`）一并返回，详情页才能回显。

网关未连接时，门户继续用本地原型状态，行为与现在保存名称 / 提示词失败时一致。提示词、基本信息、路由规则的保存字段保持不变。不在这一期改分析算法，只让界面能改已经参与分析的那份表清单。

写操作记审计（Skill id、操作人、改了哪些字段；不把完整提示词正文写入审计）。

## 4. 测试
- 从列表进入详情、返回列表，侧栏仍高亮「Skill 配置」。
- 基本信息、提示词（或路由规则）保存后出现未发布新版本；版本管理页签能看到，并发版 / 回滚路径可用。
- 引用的表可增删并保存；再次进入详情能读到；无效表名会被拒绝。
- 无编辑权限的账号只能看，不能保存或发版。
- 原有 Skill 列表、上线开关、灰度用户对话框的端到端用例改走新页面，不再依赖已删除的抽屉选择器。
- 现有分析相关测试：有 `spec.tables` 的 Skill 行为不变。

## 不在范围内
- 不把 Skill 配置改成可视化编排或 Prompt 分段模板（除非以后单独做）。
- 不在本期做「按 Skill 批量配置表管理里的表」；表归属仍按业务线管理，Skill 只引用表。
- 不在未得到明确确认前推送或生产发版。
