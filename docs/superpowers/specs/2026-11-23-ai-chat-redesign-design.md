# AI 对话改版与能力导览设计

日期：2026-11-23

## 目标与原因
现在的 AI 对话页「没质感」，而且用户多是小白，**不知道该问什么**，也不知道 agent 能做到哪一步。这次要解决两件事：

1. **对话页整体换质感**：参考 ChatGPT / Claude 一类 agent 产品的做法，不是只改配色。
2. **能力导览**：新增一个区域，用视频或图文告诉用户 agent 能做什么、要补充什么、做不了什么，并给出可以直接点用的问法。点开后不能是纯文字。

成功标准：新用户进入页面后，不需要任何培训，也能点一张卡片问出第一个问题；想知道"这个能不能做"时，一步能打开答案。

## 不做什么（非目标）
- 不改后端对话接口、Skill 路由逻辑、报告生成逻辑。
- 不做「答不了时自动弹边界说明」（需要后端识别，留作以后）。
- 不做单独的「能力中心」整页（已评估：小白不会主动点进去）。
- 不制作视频本身。视频由用户用 Muse 生成，本次只预留视频位，并由我另外出脚本。

## 反目标（做成这样就算失败）
- 看起来换了皮，但小白仍然不知道问什么。
- 能力导览写成一堵文字墙，或者点开只有文字。
- 改版后原有功能（@ 引用表、选业务线、选模型、思考强度、澄清提问卡、报告卡、换技能、反馈、追问、上下文切换提示）丢失或行为变化。

## 现状（读代码得到）
- 页面在 [page-analysis-workbench.js](../../../assets/portal/page-analysis-workbench.js)，模板是写在 JS 里的 Vue 模板字符串，用 Element Plus。样式在 `assets/portal-vue-module.css`。
- 同一批 `.portal-vue-ai-*` 类在 CSS 里写了两遍（约 446–520 行，和约 990 行起的「对话区」覆盖块），后者覆盖前者，样式有叠加。
- 图标全是 emoji，logo 是一个「灵」字；回答放在灰/白气泡里，气泡内再套计划条、口径条、报告卡、元信息卡、反馈、追问。
- 欢迎页由 `starterSuggests`（试试这样问的 chip）和三条文字 tips 组成。
- 工作台场景已由「Skill 配置」驱动：每个 Skill 有 `icon / title / displayDesc / sort / scenarioKey / enabled`（见 core.js 的 `skillRegistrySeed`），目前有数据查询、数据资产问答、数据血缘、指标异动诊断，以及通用分析路由。
- 已有自动化测试依赖若干 `data-test` 标记（`ai-starter`、`ai-followup(s)`、`ai-plan`、`plan-change`、`plan-to-report`、`ai-scope`、`ai-context-reset`、`model-chip`、`ai-line-select`）。

## 已确认的决定
- 做法选 **A：欢迎页卡片 + 右侧抽屉**（已看过效果图并确认方向）。
- 分两步实现：**① 对话页改版 ② 能力导览**，同一份设计，各自一次实现。
- 能力卡片的核心是「怎么问」：每张卡有一句真实问法，点「试一试」直接填入输入框。
- 视频由用户用 Muse 生成，我提供脚本；图文版作为视频到位前的默认内容，也作为长期备选。

## 方案对比
| 方案 | 做法 | 取舍 |
|---|---|---|
| **A（选定）** 欢迎页卡片 + 右侧抽屉 | 进入页面就能看到卡片；对话中随时可打开抽屉 | 改动适中，入口最容易被看到 |
| B 独立「能力中心」页 | 放在「分析资产」旁边，内容最丰富 | 小白不会主动点进去 |
| C 只在答不了时提示 | 最自然 | 需要后端配合；用户在第一次碰壁前一无所知 |

## 第一步：对话页改版

### 布局
- 左侧会话栏从 300px 收窄到约 150–180px；保留「新的分析」「分析资产」入口和会话列表（含飞书机器人来源标记）。会话行里的标签、状态收得更轻，只保留标题与相对时间，渠道用一个小图标表示。
- 对话区去掉灰底，用页面底色；内容居中，最大宽度约 760px，比现在更宽松。

### 消息
- **用户消息**：保留右侧气泡（浅色，沙色气泡，不用渐变和阴影）。
- **回答**：去掉气泡，整块正文，左侧是小头像（墨色圆角方块 + 衬线「灵」）。
- **「本次用了什么技能、口径、数据来源」**（原计划条 `ai-plan`、口径条 `ai-scope`、元信息卡）收成正文上方一行：「已用「单表分析」查了「xx 表」· 看依据」。点「看依据」展开：口径、数据来源、「换一个」技能 / 改为报告。**这些功能和 `data-test` 标记保持不变，只改位置和样式**。
- **思考过程**：默认收起成一行；流式生成中可展开。去掉 emoji。
- **报告卡**：保留，改成线框卡片，一行标题 + 摘要 + 「打开」。
- **反馈、追问**：反馈用线性图标按钮；追问 chip 用细边框、无填充。
- **澄清提问卡**（`msg.ask`）：保留全部交互，只统一边框、圆角、字号。

### 输入框
- 悬浮的大圆角输入卡片，放在对话区底部，不再是通栏灰条。
- 业务线、模型、思考强度保留为卡片内的小 chip；发送按钮改成圆形图标按钮；`@` 引用表的面板保留。

### 视觉规则
- **视觉配色与字体按 [Ink & Paper 视觉规范](2026-11-23-ai-chat-design-system.md) 执行**（暖纸色底 + 墨色文字 + 深松绿单一强调色，标题用衬线体，不沿用站点蓝）。用户确认「原先配色太丑」后改。
- 所有 emoji 换成线性图标（项目里没有图标库时，用现有 SVG 风格自绘或 Element Plus 自带图标；不新增外部依赖）。
- 圆角、边框、投影见视觉规范；不用渐变和发光。
- **顺手清理样式**：把两处重复的 `.portal-vue-ai-*` 样式合并成一套，不改变其它页面样式。

## 第二步：能力导览

### 入口（两处）
1. 欢迎页：能力卡片下面一行链接「我能做什么，不能做什么 ›」。
2. 对话页：输入框卡片旁一个常驻的「能力」图标按钮。

### 欢迎页（取代现在的文字 tips 和 chip）
- 标题「你好，想分析点什么？」+ 一行副标题「不知道问什么？点一张卡片，我带你试一遍」。
- 2×2 能力卡片：图标、名称、一句示例问法、「30 秒看示例」（有视频）或「图文说明」（无视频）。
- 点卡片 = 打开该能力的详情弹层（见下）。
- 现有 `starterSuggests`（含按权限个性化的权益问法）保留为卡片下方一行「你也可以问」，继续用 `data-test="ai-starter"`；原因是 e2e 校验了权益用户的个性化首屏问法。

### 右侧抽屉「我能帮你做什么」
按三组列出，每项一行：缩略图（视频或图文标识）、名称、一句话说明。
- **直接能做**
- **要你补充信息**（例如需要先选业务线）
- **暂时做不了**：每项除了说明，还要给出「可以改问：…」的替代方向。

点任意一行打开详情弹层。

### 详情弹层
- 顶部：视频位（16:9，带封面与播放按钮，时长标签）；右上角「视频 | 图文」切换。没有视频的能力只显示图文（3–4 张步骤图，每张一行说明）。
- 中部：能力名称、一句话说明。
- **示例问法**一行 +「试一试」：点击后关闭弹层，把问法填入输入框并聚焦，不自动发送。
- 底部：一行「边界」说明（浅色提示条）。

### 内容的来源与数据结构
每项能力一条记录：

| 字段 | 说明 |
|---|---|
| `id`、`group` | 分组：`can`（直接能做）/ `need`（要补充信息）/ `cannot`（暂时做不了） |
| `title`、`summary`、`icon` | 名称、一句话说明、图标 |
| `example` | 示例问法（`cannot` 组为「可以改问」的问法） |
| `video` | 可选：`{ src, poster, duration }`；没有则只显示图文 |
| `steps` | 图文版：`[{ image, text }]` |
| `boundary` | 边界说明一句话 |
| `skillKey` | 可选：关联的 Skill `scenarioKey`，用于与 Skill 配置保持一致 |

「直接能做」的 4 张卡对应现有 Skill：数据查询（看趋势）、指标异动诊断（找原因）、数据资产问答（查口径）、数据血缘（查影响）。**Skill 在「Skill 配置」里被下线时，对应卡片同步隐藏。**

## 我的决定（用户没有明确说过，请核对）
- 能力内容第一版写成**前端静态数据**，放在新文件 `assets/portal/ai-capabilities.js`，字段按上表设计，以后需要后台可配时再迁到 Skill 配置里，不需要改弹层。原因：网关的 Skill 配置接口现在不接受这些字段，改它是后端工作，超出本次范围。
- 视频文件先按相对路径引用，约定放在 `assets/guide/` 下（如 `assets/guide/trend.mp4` 和 `trend.jpg`）；用户用 Muse 生成后放进去并改 `ai-capabilities.js` 里的 `video` 字段即可。
- 「暂时做不了」和各项「边界」文案先由我根据现有 Skill 与网关行为起草，**标为草稿，上线前需要你确认事实**（例如示例图里写的「数据是昨天及以前」我没有验证）。
- 图文版的配图第一版用示意性的 SVG / 静态图，由我生成；以后可替换成真实截图。
- 不新增外部依赖；图标和弹层、抽屉沿用 Element Plus。
- 静态资源版本号（`index.html` 里的 `?v=`）随改动递增，沿用项目惯例。
