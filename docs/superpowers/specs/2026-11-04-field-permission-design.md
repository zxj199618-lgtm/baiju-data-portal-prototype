# 字段权限设计

日期：2026-11-04

## 目标
在现有「表权限」之下增加字段级权限：管理员可以对某个权限组的某张表，取消勾选个别字段。被取消的字段对该组用户**完全隐藏**（看不到字段名、查不到值，AI 也不知道有这个字段）。服务端强制，不是前端隐藏。

## 已确认的决定
- 隐藏方式：完全隐藏，不做脱敏、不做多级标签。
- 配置方式：白名单体验——勾选一张表时字段默认全勾，点进去取消个别字段。
- 存储：只记被取消勾选的字段，因此表上新增的字段默认可见；表管理里提示管理员确认新增字段。
- 个人追加：沿用现有规则，组授予的不可取消；个人可以把组里被取消的字段追加回来。
- 门户管理员组（全部数据表）不可限制字段。

## 数据结构
权限组新增 `hiddenFields`：

```json
"hiddenFields": { "用户订单明细": ["phone", "user_id"] }
```

- 只存被取消的字段。
- 保存校验：表必须在该组 `tables` 内；字段必须真实存在于该表；管理员组与「全部数据表」不允许有 `hiddenFields`。
- 表被取消授权时，该表的 `hiddenFields` 一并清除。
- `org-store.cjs` 新增 `hiddenFieldsOf(账号, 表名)`，返回不可见字段集合（组的 hiddenFields 扣除个人追加）。它是全系统唯一判断来源，与 `tablesOf` 平级。

## 服务端强制：入口处一次裁剪
网关每次请求用 `hiddenFieldsOf` 生成当前用户的「权限视图」：
- 表定义去掉被隐藏字段（名称、类型、注释、枚举值）；
- `rowsOf(表)` 每行去掉被隐藏的列。

视图传给取数工具集与语义层，替代原始 `tables` / `rowsOf`；下游不改判断逻辑。

| 入口 | 表现 |
|---|---|
| search_tables / get_schema | 字段列表、关键词匹配（含注释）、样例行都不出现 |
| run_metric / query_metric / attribute_change | 以被隐藏字段做指标、分组、筛选、归因维度，统一返回「字段不存在」，与乱写字段名提示一致 |
| 语义层指标 | 依赖字段被隐藏则该表上指标不可用，list_metrics 不列；比率指标任一字段被隐藏则整体不可用 |
| /v1/analyze 证据 | 字段清单、聚合、明细样例走裁剪视图 |
| 推荐问题 | 基于裁剪视图 |
| get_lineage | 表级，不受影响；落地时核对是否带字段名，有则裁剪 |

被隐藏字段名不出现在任何给模型的提示词里。保存权限与被拒访问写入已有审计日志。

## 已知边界
工作台历史、证据账本、已生成报告保存的是当时权限下的结果，之后收紧权限不追溯清除；管理页注明此点。

## 界面（page-permission-config.js，权限组与用户管理的「表权限」标签页）
- 每张表右侧显示「字段 n/m」标签（全选时显示「全部字段」）。
- 点标签展开字段面板（名称、类型、注释）：勾选表时全选；可取消个别字段；顶部「全选」恢复。
- 用户页中组授予的表/字段灰色锁定，带权限组标签；个人追加的字段可勾。
- 「全部数据表」与管理员组不显示字段面板。
- 取消授权表时清除其字段设置。
- 新增字段提醒：表字段比上次确认多时，该表显示小红点「新增 N 个字段，请确认」；管理员打开面板确认后消失，不阻塞操作。

## 测试（node:test）
- 存储单元：hiddenFieldsOf 合并规则；保存校验（表未授权、字段不存在、管理员组被拒）；取消授权清除字段设置。
- 取数工具：被隐藏字段在 search_tables、get_schema、样例行不出现；做指标/分组/筛选时提示与乱写字段名一致；依赖指标从 list_metrics 消失。
- 网关端到端：管理员给某组隐藏字段后，该组用户问该字段取不到；恢复后立即可用。
- 回归：现有表权限测试与评测用例保持通过。

## 不做
脱敏、多级敏感标签、历史记录追溯清除。
