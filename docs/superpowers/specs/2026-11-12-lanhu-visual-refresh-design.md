这份说明取代 `docs/superpowers/specs/2026-11-12-auli-visual-refresh-design.md`。不要按 Auli 那份规范实现。

色值来自用户导出 PNG 中大面积纯色区域的众数取样，**不是**蓝湖标注面板里的官方值。文中色值均视为「取样」。字体、精确字号、圆角、阴影无法从导出图可靠量出：实现时按视觉贴近设计图，不要编造一套新字体规范。

## 原则

- 唯一设计来源是上述蓝湖项目，不是 Auli。
- 有设计图的页面，严格按对应画板。同一页面出现在多个文件夹时，用较新的那份：AI中心、权限管理细化、V3 优先于 V2、V1。
- 没有设计图的页面，跟项目附录和本文取样色值，不另起一套风格。布局可参考已有列表页和详情页（如用户管理、表详情）。
- 左侧菜单布局不变。现有 11 个一级分组都保留，不删、不重组。设计图里还没有的「大数据工具箱」「业务工具箱」「AI 中心 / Skill 配置」也保留，样式跟附录看齐。
- 菜单文案先保持现状：「数据告警」不要改成设计图里的「数据警告」，除非另有明确要求。
- 图上红色虚线注释（如「logo更换」「新增配置权限」）是设计师说明，不是界面色。Logo 先保留现稿（Stardata + 观星台），不要自行画新 logo。
- 用户管理操作列按图增加「配置权限」入口（样式为灰色操作文字）；若该功能尚无后端，做样式与入口，不要假造完整权限配置业务。

## 范围

要做：

- 全局主色、侧栏、按钮、表格、表单、标签、抽屉、筛选条对齐设计图
- 所有已有设计图的页面按对应画板还原视觉
- 没有设计图的页面用同一套附录规范

不做：

- 不改菜单结构，不删、不重组现有分组
- 不自行换新 logo
- 不把本机暂存的样式或业务线改动（stash / `/tmp/gxt-wip-style-bizline`）混进来
- 不合并到 main，不推送（由协调者决定），不发版、不部署生产

## 实现约束

- Vue 3 + Element Plus 门户。侧栏是左侧 `el-menu`。导航数据在 `assets/portal-bridge.js` 的 `simpleNav`（11 组）。
- 把设计 token 收敛到可维护的全局样式（CSS 变量或主题覆写），避免每个页面各写一套硬编码色。
- 不要把 Element Plus 默认 `#1677ff` 留在主色、选中态、主按钮上。
- 不要改业务逻辑；视觉还原时若缺交互或接口，保持现有行为，只改样式。
- 「配置权限」若无现成页面，先做入口样式，可暂用占位或现有权限相关跳转，不要编造完整新业务。
- 在新分支上改，分支名建议 `feat/lanhu-visual-refresh`，不要提交到 main。
- 不要读取、提交或回显 `.env`、`.deploy.env` 或任何密钥。
- 提交信息用中文或英文均可，说明这是按蓝湖取样规范的视觉改版。
- 把本说明放入仓库 `docs/superpowers/specs/2026-11-12-lanhu-visual-refresh-design.md`，并在已废弃的 Auli 文档开头加醒目说明：已废弃，改以蓝湖这份为准。
